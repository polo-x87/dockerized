The mobile MCP stack connectors

MCP (Model Context Protocol) gives AI models the "eyes and hands" required for mobile dev. Three open-source servers cover the typical surface area:

@mobilenext/mobile-mcp

Most robust cross-platform UI driver. Uses adb (Android) and xcrun simctl (iOS) alongside native Accessibility APIs.

ToolPurpose
get_ui_treeReads the on-screen widget hierarchy
tap_elementClick by text, accessibility ID, or coordinates
swipeScrolling through lists or pages
take_screenshotVisual verification back to a vision model

@expo/mcp-server

Gold standard for React Native dev. Reads the exact SDK-version docs, controls EAS (cloud builds + deployments), pulls crash logs from TestFlight / Play Console, manages deps via npx expo install.

Marionette MCP (Flutter)

Connects directly to the Flutter VM Service — bypasses the opaque accessibility tree. Tap widgets by Dart Key or Widget type, run integration smoke tests.

Cursor vs. Claude Code — two workflow styles

Cursor: closed-loop visual

  1. Editor on one side, simulator on the other.
  2. mobile-mcp wired in Cursor settings.
  3. Prompt → code → trigger hot reload → screenshot → vision-analyze → self-correct.
"Build a settings screen with a dark mode toggle. Run it on the simulator." → Cursor writes the SwiftUI / Compose / RN, takes a screenshot, notices misalignment, adjusts padding.

Claude Code (CLI): DevOps & architecture

Best for refactors and CI/CD across thousands of files.

"Upgrade React Native 0.73 → 0.74. Handle breaking changes, update the Podfile, run the iOS build." → reads Expo MCP docs, runs npm install / pod install / xcodebuild, parses log on failure, patches Obj-C/Java autonomously, retries.
Dev containers vs. host emulators — the bridging problem

When Cursor runs inside a Linux dev container and emulators run on macOS, MCP commands execute inside the container. xcrun simctl is macOS-exclusive and cannot be installed in Linux — period.

Android (easy)

  1. Start the emulator on macOS.
  2. Ensure ADB server is running: adb start-server on the Mac.
  3. Install adb client in the dev container.
  4. Point the client at the host: export ADB_SERVER_SOCKET=tcp:host.docker.internal:5037.

iOS (requires SSE)

  1. Run mobile-mcp directly on the Mac host.
  2. Expose it over SSE (Server-Sent Events), e.g. http://host.docker.internal:8080/mcp.
  3. Configure Cursor inside the container to point at the SSE URL instead of a local command.

Note: if Cursor's UI doesn't accept SSE directly, run a small in-container proxy that bridges stdio ↔ the host SSE socket.

The devbox container portable dev box

A slim Debian-bookworm Docker image, multi-stage build, target size ~1.5 GB (Swift toolchain lives in an optional sidecar image). Runtime on OrbStack (free for personal use; falls back to Docker Desktop or Podman).

Three modes

  1. Long-lived dev box. Start once, survive Mac reboots, SSH in.
  2. AI agent sandbox. Ephemeral, no host mounts, destroyed on exit.
  3. Per-project dev container. Each repo's .devcontainer/ extends the base.

Common problems & fixes
"permission denied (publickey)" on devbox ssh
Public key in base/.env (DEVBOX_HOST_SSH_PUBKEY) must match the private key in ~/.ssh/config. Defaults: ~/.ssh/devbox_ed25519.pub ↔ ~/.ssh/devbox_ed25519. install-host.sh handles both.
"port 2222 already in use"
Edit base/docker-compose.yml, change the host-side of 127.0.0.1:2222:22, update ~/.ssh/config to match.
"docker: not found" inside the container
The CLI is installed but needs /var/run/docker.sock bind-mount. Compose does this; docker run one-offs may have omitted it.
Docker permission errors on the socket
entrypoint.sh re-aligns the docker group's GID to the mounted socket. If you bypassed the entrypoint, sudo until you reinvoke it properly.
Slow bind-mounted ~/code
You're on Docker Desktop's default. Switch to OrbStack (VirtioFS) — dramatically faster.
tmux sessions don't restore
First time only: run tmux, press Ctrl-a + I (capital i) to install plugins via tpm. After that, continuum autosaves every 15 min and restores on launch.
Claude/Codex/Gemini missing config
Run each once interactively to auth. Configs persist in the devbox-config named volume across rebuilds.
Image > 2 GB
docker history devbox-base:latest shows the heaviest layer. Usual suspects: too many cargo binaries baked in; move some to a per-project overlay. Swift is already in a separate sidecar (Dockerfile.swift) to keep base at ~1.5 GB.
Research-system Dockerfile pattern Python multi-stage

From dockerize/mcp_workflow.md — containerize a Python "Research Routine" (master + agents) with minimal final image and SQLite-backed persistence.

Multi-stage Dockerfile

# --- Stage 1: Builder ---
FROM python:3.11-slim as builder

WORKDIR /app

ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1

RUN apt-get update && apt-get install -y --no-install-recommends gcc python3-dev

COPY research_system/requirements.txt .
RUN pip install --user --no-cache-dir -r requirements.txt

# --- Stage 2: Runner ---
FROM python:3.11-slim as runner

WORKDIR /app

COPY --from=builder /root/.local /root/.local
COPY research_system/ .

ENV PATH=/root/.local/bin:$PATH

VOLUME ["/app/data"]

CMD ["python", "master.py"]

Compose with master + N agents

version: '3.8'
services:
  master:
    build: .
    image: research-system:latest
    container_name: research_master
    volumes:
      - ./research_data:/app/data
    env_file:
      - .g_env
    restart: always

  agent-1:
    image: research-system:latest
    container_name: research_agent_1
    command: python agent.py 1
    volumes:
      - ./research_data:/app/data
    env_file:
      - .g_env
    depends_on:
      - master

AI agent secrets — env vs 1Password

Option A: env vars at runtime (simple)

In base/.env:

ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...
GEMINI_API_KEY=...

Downside: keys live in plaintext on disk.

Option B: 1Password CLI at runtime (recommended)

  1. Sign into op from the host once (biometric).
  2. Forward op via SSH agent or mount a service-account token.
  3. Wrap each agent invocation with op run:
op run --env-file=~/.config/op/claude.env -- claude

# claude.env:
ANTHROPIC_API_KEY=op://Personal/Anthropic/api_key

Tick each step as you go. Progress persists across reloads. Some steps depend on choices in the Configure tab — MCP wiring shows the platforms you picked there.
